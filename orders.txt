# TSKCONNECT — ADVANCED ORDER BATCH & DELIVERY MANAGEMENT SYSTEM

> **IMPORTANT:** Extend the existing Tskconnect platform with a powerful Order Batch / Export Batch management system.
>
> The system must support MTN, Telecel and AirtelTigo independently.
>
> Do not treat every individual recipient as a separate row on the main admin/user order history. Instead, introduce a **Batch Order** concept that groups multiple recipients submitted/exported together while retaining every individual order underneath it.

---

# 1. CORE CONCEPT — ORDER BATCHES

When a reseller submits multiple recipients at once, Tskconnect should create:

```text
ORDER BATCH
   │
   ├── Recipient Order 1
   ├── Recipient Order 2
   ├── Recipient Order 3
   ├── Recipient Order 4
   └── ...
```

Example:

```text
Batch: CF-BATCH-000184
Network: MTN
Recipients: 20
Total Data: 100 GB
Total Amount: GHS 380.00
Status: PENDING
Created: Sep 10, 2026 — 09:42 AM
```

The individual recipient orders remain stored separately in the database.

This allows:

* batch-level management
* individual order management
* batch-level exporting
* individual status changes
* batch status changes
* delivery reporting
* recipient-level "Not Received" reports

# 2. NETWORK SEPARATION

Tskconnect supports:


Never mix different networks inside the same export batch.



If an upload contains multiple networks, automatically separate the orders into network-specific batches.

# 31. EXCEL EXPORT TRANSACTION

The export operation must follow this order:

```text
1. Select eligible pending orders
        ↓
2. Lock/verify eligible orders
        ↓
3. Generate Excel file
        ↓
4. Confirm file generation succeeded
        ↓
5. Create ExportBatch record
        ↓
6. Change selected orders:
   PENDING → PROCESSING
        ↓
7. Record status history
        ↓
8. Record audit log
        ↓
9. Return downloadable file
```

If anything fails before the status update:

```text
DO NOT change the orders to PROCESSING.
```

This prevents orders from disappearing from the pending queue because of an export error.

## One important improvement I strongly recommend

Add an **"Operations Queue"** to the admin dashboard.

It could look like:

```text
┌─────────────────────────────────────────────┐
│ OPERATIONS QUEUE                            │
├─────────────────────────────────────────────┤
│                                             │
│ MTN                                         │
│ 20 Pending       100 GB       [Export]      │
│                                             │
│ Telecel                                     │
│ 14 Pending        70 GB       [Export]      │
│                                             │
│ AirtelTigo                                  │
│ 18 Pending        90 GB       [Export]      │
│                                             │
└─────────────────────────────────────────────┘
```

That way, when you open the admin panel, you immediately know:

**"MTN has 20 orders waiting. Telecel has 14. AirtelTigo has 18."**

One click exports each queue, moves those orders into **Processing**, and creates the corresponding export batch.
