================================================================================
     TSKCONNECT — VERCEL DUAL-DOMAIN DEPLOYMENT & TESTING GUIDE
     (How to Use Two Separate Domains or Subdomains on One Vercel Project)
================================================================================
Repository: https://github.com/Loveago/tsk.git
Framework:  Next.js 15 (App Router) + Prisma + Tailwind CSS
Platform:   Vercel

You can use two separate domains on the SAME Vercel project:
• Domain 1 (Management Portal): For Admin, Users, Billing, and Dashboard.
• Domain 2 (Storefront Portal): Dedicated to Customers, Stores, and Order Tracking.

This works whether you use:
• Two free Vercel subdomains (e.g. `tsk-admin.vercel.app` & `tsk-store.vercel.app`)
  OR
• Two custom domains (e.g. `tsk05.net` & `tskdatastore.com`)
================================================================================

================================================================================
STEP 1: ADD BOTH SEPARATE DOMAINS TO YOUR VERCEL PROJECT
================================================================================
Go to your **Vercel Project Dashboard** -> **Settings** -> **Domains**.

--------------------------------------------------------------------------------
OPTION A: Using Two Free .vercel.app Subdomains (Instant, No DNS setup needed)
--------------------------------------------------------------------------------
Vercel allows you to add multiple `.vercel.app` aliases to the exact same project!

1. Your primary domain is already there (e.g. `my-portal.vercel.app`).
2. In the "Add Domain" box, type a second `.vercel.app` subdomain for your stores:
   Example: `my-storefront.vercel.app`
3. Click "Add".
4. Vercel automatically assigns it instantly with SSL!

You now have two distinct domains pointing to your app:
• `my-portal.vercel.app`
• `my-storefront.vercel.app`

--------------------------------------------------------------------------------
OPTION B: Using Two Custom Domains (e.g. tsk05.net & tskdatastore.com)
--------------------------------------------------------------------------------
1. In Vercel Project -> Settings -> Domains:
   - Add `tsk05.net` and `www.tsk05.net`
   - Add `tskdatastore.com` and `www.tskdatastore.com`
2. In your DNS provider (Namecheap, Cloudflare, GoDaddy, etc.), set:
   For tsk05.net:
     A record:     @   ->  76.76.21.21
     CNAME record: www ->  cname.vercel-dns.com
   For tskdatastore.com:
     A record:     @   ->  76.76.21.21
     CNAME record: www ->  cname.vercel-dns.com


================================================================================
STEP 2: SET THE DUAL-DOMAIN ENVIRONMENT VARIABLES IN VERCEL
================================================================================
Go to: **Settings** -> **Environment Variables** in your Vercel Project.

Add / Update these 4 domain variables:

(Replace with your two chosen domains, WITHOUT `https://`):

| Variable Key                   | Example (Option A: Vercel)    | Example (Option B: Custom) |
| :----------------------------- | :---------------------------- | :------------------------- |
| MAIN_DOMAIN                    | my-portal.vercel.app          | tsk05.net                  |
| NEXT_PUBLIC_MAIN_DOMAIN        | my-portal.vercel.app          | tsk05.net                  |
| STOREFRONT_DOMAIN              | my-storefront.vercel.app      | tskdatastore.com           |
| NEXT_PUBLIC_STOREFRONT_DOMAIN  | my-storefront.vercel.app      | tskdatastore.com           |

Also ensure your other required variables are set:
• DATABASE_URL: Your cloud Neon/Postgres pooling connection string
• AUTH_SECRET: 32+ character random secret
• PAYSTACK_SECRET_KEY: sk_test_... (or sk_live_...)


================================================================================
STEP 3: UPDATE DATABASE SCHEMA (PRISMA DB PUSH)
================================================================================
Push the latest storefront database schema to your cloud database:

From your local machine terminal:
DATABASE_URL="your_neon_postgres_url" npx prisma db push


================================================================================
STEP 4: REDEPLOY THE PROJECT ON VERCEL
================================================================================
1. Push your latest code to GitHub:
   git add .
   git commit -m "Configure multi-domain routing"
   git push origin main

2. Or in Vercel Dashboard:
   Go to the "Deployments" tab -> click the `...` menu on the latest deployment -> select "Redeploy".
   (Uncheck "Use existing Build Cache" so it loads the updated domain variables).


================================================================================
STEP 5: VERIFY HOW THE TWO DOMAINS INTERACT
================================================================================

1. MANAGEMENT DOMAIN (e.g. `https://my-portal.vercel.app`):
   • Open `https://my-portal.vercel.app/login` -> Logs in to management dashboard.
   • Open `https://my-portal.vercel.app/@storename` -> Automatically redirects to
     `https://my-storefront.vercel.app/storename`!

2. STOREFRONT DOMAIN (e.g. `https://my-storefront.vercel.app`):
   • Open root `https://my-storefront.vercel.app/` -> Renders the Inquisitive Visitor homepage.
   • Open `https://my-storefront.vercel.app/kofi-data` -> Renders the customer store.
   • Open `https://my-storefront.vercel.app/kofi-data/mtn` -> Clean network page.
   • Open `https://my-storefront.vercel.app/admin` -> Instantly redirects to
     `https://my-portal.vercel.app/login` for security!

================================================================================
STEP 6: TESTING WITH A FREE VERCEL DOMAIN (NO DNS / NO DATA-DEALS.COM NEEDED)
================================================================================
You DO NOT need to touch `data-deals.com` or alter any DNS records to test the
custom storefront. You can test everything 100% free right inside Vercel using
a custom `.vercel.app` domain alias!

Here is the exact step-by-step walkthrough:

--------------------------------------------------------------------------------
1. ADD A FREE VERCEL SUBDOMAIN ALIAS
--------------------------------------------------------------------------------
1. Go to your **Vercel Project Dashboard** (https://vercel.com).
2. Click on **Settings** -> **Domains**.
3. In the input box, type any unique name ending in `.vercel.app`.
   Example:
   `datadeals-test.vercel.app`   (or `my-datadeals.vercel.app`)
4. Click **Add**.
   • Vercel will instantly generate the domain and issue a free SSL certificate.
   • No DNS setup is required at all! It is active immediately.

--------------------------------------------------------------------------------
2. CONFIGURE THE ENVIRONMENT VARIABLE
--------------------------------------------------------------------------------
Tell your Next.js application that this new domain is the custom store host:

1. In the same project on Vercel, go to **Settings** -> **Environment Variables**.
2. Add a new variable:
   • **Key**: `ADMIN_CUSTOM_DOMAIN`
   • **Value**: `datadeals-test.vercel.app` (use the exact name you added in step 1, without https://)
   • **Environments**: Check all (Production, Preview, Development)
3. Click **Save**.

--------------------------------------------------------------------------------
3. REDEPLOY TO APPLY THE ENVIRONMENT VARIABLE
--------------------------------------------------------------------------------
Environment variables only take effect on new deployments:

1. Go to the **Deployments** tab in Vercel.
2. Find your latest deployment, click the **three dots (...)** on the right.
3. Click **Redeploy**.
4. (Optional but recommended) Uncheck "Use existing Build Cache" so it builds fresh.
5. Wait ~1-2 minutes for the deployment to finish.

--------------------------------------------------------------------------------
4. HOW TO TEST & VERIFY
--------------------------------------------------------------------------------
Once the redeploy finishes, open your browser and test the URLs:

1. **Root Storefront (Clean URL)**:
   • Visit: `https://datadeals-test.vercel.app/`
   • Result: Loads your Data Deals store directly — no `/store/...` or slug in the address bar!

2. **Network Purchasing Pages**:
   • Visit: `https://datadeals-test.vercel.app/mtn`
   • Visit: `https://datadeals-test.vercel.app/telecel`
   • Visit: `https://datadeals-test.vercel.app/airteltigo`
   • Result: Direct access to bundle selection with custom pricing.

3. **Order Tracking**:
   • Visit: `https://datadeals-test.vercel.app/track`
   • Result: Customer order lookup page works seamlessly.

4. **Security Protection Check**:
   • Visit: `https://datadeals-test.vercel.app/admin` or `https://datadeals-test.vercel.app/dashboard`
   • Result: Instantly blocked and safely redirected to your main portal login! Customers can never access admin pages through the store domain.

5. **Admin Management & Dedicated Wallet Test**:
   • Open your main admin portal (e.g., `https://my-portal.vercel.app/admin` or `https://tsk05.net/admin`).
   • Click the **data-deals Store** link in the navigation menu (`/admin/custom-storefront`).
   • Check that the dedicated wallet balance, revenue, and profit cards display properly.
   • Edit a price or banner notice under "Settings & Branding" -> click Save.
   • Refresh `https://datadeals-test.vercel.app/` -> the changes appear instantly!

--------------------------------------------------------------------------------
5. WHEN YOU ARE READY TO LAUNCH ON DATA-DEALS.COM (LATER)
--------------------------------------------------------------------------------
Whenever you are satisfied with testing and ready to switch to `data-deals.com`:

• **If launching on Vercel**:
  1. In **Settings** -> **Domains**, add `data-deals.com` and `www.data-deals.com`.
  2. In your DNS manager, point the A record `@` to `76.76.21.21` and CNAME `www` to `cname.vercel-dns.com`.
  3. In **Settings** -> **Environment Variables**, change `ADMIN_CUSTOM_DOMAIN` to `data-deals.com` (or remove it, as `data-deals.com` is already the default).
  4. Redeploy.

• **If launching on VPS (Nginx)**:
  1. Follow the step-by-step Nginx + Certbot guide in `vps.txt` (Section 14).
  2. Point your DNS A record to your VPS IP address.
