Introduction
The BIGWIN api lets you place data bundle orders, register AFA enrollments, query your wallet, and receive real-time order status updates via signed webhooks — all from your own systems.

All requests use JSON over HTTPS. Successful responses return 200 OK with a status: "success" wrapper. Errors return appropriate 4xx/5xx codes with status: "error" and an errors[] array.

Authentication
Every request must include your API key in the X-API-Key header. Requests with a missing, invalid, or revoked key receive 401 Unauthorized.

Authenticated Request
Copy
curl "https://bigwindatagh.com/api/balance" \
  -H "X-API-Key: ak_eaccfe263cfab291ea6e240ad52c2a954c1d9b5df580864f"

Webhooks
When an order or AFA registration changes status, PRISTAR POSTs a signed JSON payload to your registered webhook URL. Configure your webhook URL in the API Dashboard.

Events
The following events trigger webhook deliveries:

order.placed
Order sent to provider
order.delivered
Successfully delivered
order.failed
Delivery failed
order.refunded
Refunded to wallet
afa.delivered
AFA registered
afa.failed
AFA failed
Signature Verification
Every request includes an X-Pristarx-Signature header — an HMAC-SHA256 of the raw request body signed with your webhook secret. Always verify this before processing.

PHP
Node
Copy
<?php
$payload   = file_get_contents("php://input");
$signature = $_SERVER["HTTP_X_PRISTARX_SIGNATURE"] ?? "";
$secret    = "your_webhook_secret";

$expected = hash_hmac("sha256", $payload, $secret);

if (!hash_equals($expected, $signature)) {
    http_response_code(401);
    exit("Invalid signature");
}

$event = json_decode($payload, true);
// process $event["event"], $event["order"], $event["afa_order"]

http_response_code(200);
echo json_encode(["received" => true]);

Retry Policy
Failed deliveries (non-2xx response or timeout) are retried up to 5 times with exponential back-off: 2, 4, 8, 16, 32 minutes. Your endpoint should return any 2xx status to acknowledge receipt. Delivery logs are visible in your API Dashboard.

Error Codes
HTTP	Code	Meaning	Resolution
401	unauthorized	Missing or invalid API key	Pass a valid active key in X-API-Key header
402	insufficient_balance	Wallet balance too low	Fund your wallet via the dashboard or /wallet/fund
404	not_found	Endpoint or resource not found	Check the URL and reference value
409	duplicate_order	Idempotency key already used	Retrieve the original order instead of resubmitting
422	validation_error	Invalid parameters	Check the errors[] array in the response body
429	rate_limited	Too many requests	Wait for Retry-After seconds before retrying
500	server_error	Internal server error	Retry with exponential back-off; contact support if persistent
